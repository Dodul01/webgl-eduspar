# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **Unity 6 (6000.4.1f1) WebGL build output** for an interactive lip-sync avatar app
("EduSpark Avatar" / product name "Urp imran"). It is a compiled artifact directory, **not**
Unity source — there are no `.cs` scripts, no Assembly, and no Unity project here. The only
human-editable file is `index.html`; everything in `Build/` is generated by Unity's WebGL
exporter and should be treated as opaque (regenerated by rebuilding in the Unity Editor, never
hand-edited).

- `index.html` — the custom hosting page and all JS glue (editable).
- `Build/` — WASM, framework JS, `.data`, and the loader, each with a Brotli (`.br`) twin.
- `TemplateData/` — static template assets (icon).
- `ProjectVersion.txt`, `GUID.txt`, `dependencies.txt` — Unity metadata (URP blank template; see
  `dependencies.txt` for the full UPM package set).

## Running locally

Must be served over HTTP (the loader uses `fetch` for WASM/`.data`; `file://` will not work):

```bash
python3 -m http.server 8080    # then open http://localhost:8080/
```

Serving the Brotli (`.br`) files requires the server to send `Content-Encoding: br`. Plain
`http.server` does not, so local dev relies on the uncompressed `Build/WebGL Builds.*` files;
the `.br` twins are for a production host configured to serve them.

There is no build/lint/test tooling in this directory. To change avatar/gameplay behavior you
rebuild from the Unity project (not present here) and replace `Build/`.

## Architecture: the JS ↔ Unity audio bridge

The entire point of `index.html`'s custom glue is to drive the Unity avatar's mouth from
browser audio. Two directions:

**Browser → Unity** via `window.unityInstance.SendMessage(...)`, targeting the GameObject named
**`CH`** (the avatar/character controller in the Unity scene). Messages used:
- `OnWebAudioStarted` / `OnWebAudioEnded` — playback lifecycle.
- `SetExternalLipSync` with a `0..1` loudness string — per-frame mouth openness.

If you rename the scene GameObject or these methods on the Unity side, the string literals in
`index.html` must be updated to match, or lip-sync silently no-ops (all `SendMessage` calls are
wrapped in `try/catch`).

**The audio engine** is expected to be injected by a Unity `.jslib` plugin as
`window.EduSpark` (or legacy `window.EternityAvatar`), exposing: `playFile`, `playBuffer`,
`playUrl`, `startMicrophone`, `stopMicrophone`, `stop`, `getAudioLevel`, `isPlaying`. The UI
(upload, mic, URL, drag-drop) calls these; `getAudioLevel()` feeds the on-page meter. The
"Test Speech" button is a fallback that uses the browser `SpeechSynthesis` API and synthesizes
a fake loudness curve to drive `SetExternalLipSync` directly — it works even when the jslib
engine is absent.

## Gotcha: loader wiring is currently blank

In `index.html` the Unity loader is **not wired up**:
- `<script src="">` (line ~426) has no `src` — should point to `Build/WebGL Builds.loader.js`.
- `unityConfig.dataUrl` / `frameworkUrl` / `codeUrl` / `streamingAssetsUrl` are empty strings.

As-is, `createUnityInstance` is undefined and the page never loads the build. Unity's default
exported template fills these with the `Build/WebGL Builds.*` paths. When fixing, note filenames
contain a space ("WebGL Builds") — URL-encode as needed. Match each config key to its file:
`dataUrl`→`.data`, `frameworkUrl`→`.framework.js`, `codeUrl`→`.wasm`.
